# 07 浏览和打开 Claude 会话

手机 App 的"全部会话"页签能列出电脑上 Claude 桌面端的全部会话，点一个就在电脑上把它开成单独窗口并进入远程画面，也能在某个环境下新建会话；"已打开"页签的卡片能把会话窗口关掉。协议见 [03](03-protocol.md) 2.5、2.8，App 端见 [04](04-android-client.md)"全部会话页签""关闭会话窗口"。这篇说被控端是怎么做到的，以及 Claude 升级后哪里可能要改。

**要点**：Claude 桌面端没有对外的接口能列会话、开窗口，被控端靠的是两样不公开的东西：Claude 的本地记录文件和它的界面文字。Claude 升级后这两样都可能变，变了就会在手机上看到"没在 Claude 界面里找到要点的菜单"之类的提示，按下面的办法查。

代码在 `host/sessions/`：

| 文件 | 作用 |
|---|---|
| `catalog.js` | 读 Claude 的本地记录，按环境分组。纯 Node，有单元测试（`host/test/sessions-catalog.test.js`） |
| `claude-ui.ps1` | 用 Windows 界面自动化（UI Automation）按名字找 Claude 界面上的按钮和菜单项并按下去。不移动鼠标、不发键盘 |
| `index.js` | 把上面两个和 Claude 的链接串起来：打开、新建（同一时间只做一件）、关闭窗口。关闭有单元测试（`host/test/sessions-close.test.js`） |

## 1. 会话从哪里来

商店版 Claude 的数据目录是 `%LOCALAPPDATA%\Claude-Data\claude_<包名>`，安装包版是 `%APPDATA%\Claude`。被控端找里面有 `claude-code-sessions` 的那个，有几个时取最近用过的。

| 文件 | 内容 | 用到的字段 |
|---|---|---|
| `ccd-session-presets.json` | 保存的环境（Code 输入框下方"环境："里列的那些） | `byAccount.<账号>.presets[]` 的 `id`、`name`、`target.cwd`、`lastUsedAt` |
| `claude-code-sessions\<账号>\<组织>\local_<uuid>.json` | 每个会话一个文件 | `sessionId`、`title`、`originCwd`/`cwd`、`startedFromEnvironmentId`、`isArchived`、`lastActivityAt` |
| `session-popouts.json` | 现在开成单独窗口的会话，窗口一开一关就更新 | `accountUuid`、`popouts[]` 的 `sessionId`、`title` |

分组规则（`buildGroups`）：会话记着从哪个环境开的就归那个环境；没记的，工作目录和某个环境相同就归它；都不是的按工作目录分组（这种组不能新建）；Claude 给"无文件夹"会话建的临时目录（路径里有 `scratch-workspaces`）归到"无文件夹"。已归档的不列。会话文件有一百多个，按修改时间缓存，第二次读只要几毫秒。

## 2. 打开一个会话

1. `session-popouts.json` 里有这个会话，且有标题对得上的 Claude 窗口：直接回这个窗口，手机去看它。
2. 否则用 Claude 自己的链接 `claude://code/continue?session=local_<uuid>` 让主窗口出来并显示这个会话。这个链接是 Claude 的"Code 入口"功能，Windows 的跳转列表里也用它。
3. 在主窗口的标题栏找"<会话标题> 的更多选项"按钮，展开 → "打开方式" → "新建窗口"。
4. 等一个新的、标题是会话名的 Claude 窗口出现。
5. 检查窗口里的页面真的显示了这个会话（页面标题等于会话名，见第 6 节"卡住的窗口"），对了就回给手机。页面还在加载（没有页面标题）时最多等 20 秒；页面显示着别的会话、6 秒还没换过来就不等了。窗口平铺在运行时会把它排好，并把主窗口收回托盘。

第 2 步之前先注入一次鼠标微动叫醒显示器，第 5 步等页面的时候每 1.5 秒再动一下（0.9.5 起）：显示器关着时 Claude 复用的窗口不刷新画面，第 5 步会一直对不上，见第 6 节。新建会话（下一节）也一样，在选环境那一步动。

## 3. 在某个环境下新建会话

1. 主窗口没显示时，先用链接 `claude://code/new` 让它出来（界面自动化看不到藏起来的窗口）。
2. 主窗口标题栏"菜单" → "文件" → "在新窗口中新建会话"，出来一个标题为"新会话"的窗口。
3. 在新窗口输入框下方展开"环境：…"，在"搜索环境"里填环境名，选中名字对得上的那一项，再确认按钮变成"环境：<环境名>"。选不上时窗口照样给手机，提示用户自己选。
4. 会话要等用户发出第一句话才真正建立，这一步在手机的远程画面里做。

`claude://code/new` 有个 `environment` 参数，但实测填环境编号并不会选上那个环境，所以第 3 步在界面里选。

为什么不在主窗口里新建：主窗口平时被平铺收在托盘里，实测用链接或 Claude 自己的"在主窗口中打开"把它叫出来后，屏幕上只显示加载中的灰色占位画面（界面自动化里页面内容是在的），远程看不到东西。单独的新会话窗口显示正常。

## 4. 关闭会话窗口

被控端给窗口发 `WM_CLOSE`（`win32.postClose`），效果和在电脑上点窗口右上角的 × 一样，不动鼠标键盘、不靠界面文字，窗口最小化或被挡住时也能关；不走界面自动化，电脑锁屏时应该也能关（没试）。发完等窗口从屏幕上消失（最多 3 秒），再回给手机。

**关闭在 Claude 桌面端上意味着什么**（6.6395，读了 Claude 的程序包、在用户电脑上实测，2026-11-19）：

- 会话窗口由 Claude 的窗口库管理，设了"关闭时隐藏"：收到关闭就把窗口藏起来，通知 Claude 的页面"用户要关这个窗口"。页面决定留着它复用还是销毁，所以第 6 节说的"关掉的窗口会被拿去开别的会话"就是这么来的。实测发出 `WM_CLOSE` 后 40 毫秒窗口就看不见了，句柄还在（`IsWindow` 为真），20 秒后仍在。
- `session-popouts.json` 里这个会话马上去掉，"全部会话"里的"已打开"标记跟着变。
- 会话本身不受影响：Claude Code 的会话由 Claude 主进程管，窗口只是显示它的地方。实测在会话正在执行命令时关掉它自己的窗口，命令照常跑完、会话接着工作。所以手机上关窗口不确认（用户定的），关掉后提示会话还在"全部会话"里。
- Claude 主窗口不会被叫出来。Claude 的代码里，关掉有焦点的会话窗口时会把焦点交给主窗口；实测主窗口收在托盘里、关掉的正是前台窗口时，主窗口也没有出来（试了一次）。
- **主窗口不能关**：Claude 的主窗口在设置里关了托盘图标时，关掉它会退出整个 Claude，所有会话都停；开着托盘时只是收进托盘。所以窗口列表里主窗口（类名 `Chrome_WidgetWin_1`、标题"Claude"）的 `closable` 是假，被控端也拒绝关它（`not-closable`）。
- **句柄会被复用**：藏起来的窗口以后可能拿去开别的会话，句柄不变、标题变了。手机发关闭时带上卡片上的标题，对不上就不关（`changed`），免得手机上的列表旧了时关错会话。
- 被控端不确定一个会话是不是在运行（Claude 的会话记录里没有这样的字段），反正关窗口不影响运行，也就不用知道。

关掉以后：给这个手机马上推一次新的窗口列表；别的手机正在看这个窗口的，发 `window-closed` 让它们回到列表（窗口只是藏起来，采集不一定会自己停，不能等采集停了再通知）。

## 5. 认的界面文字

`claude-ui.ps1` 开头的 `$L` 表，目前认简体中文和英文：

| 用途 | 简体中文 | 英文 |
|---|---|---|

| 打开方式 | `打开方式` | `Open in` |
| 新窗口 | `新建窗口` | `New window` |
| 标题栏菜单 | `菜单` | `Menu` |
| 文件菜单 | `文件` | `File` |
| 新窗口里新建 | `在新窗口中新建会话` | `New Session in New Window` |
| 环境按钮 | `环境：{环境名}` | `Environment: {环境名}` |
| 搜索环境 | `搜索环境` | `Search environments` |
| 确认框：允许一次 | `允许一次` | `Allow once` |
| 确认框：更多允许选项（下拉） | `更多允许选项` | `More allow options` |
| 确认框：始终允许 | `始终允许` | `Always allow` |
| 确认框：拒绝 | `拒绝` | `Deny` |

英文是从 Claude 程序包里的英文文案查到的，没在英文界面上实测；确认框那四个的英文是猜的，没查过。

最后四个是会话里桌面端自己弹的确认框的按钮。确认框有两种样子：每次操作都问的（"允许 Claude 在 xxx 上执行 JavaScript？"）一行里是"拒绝""允许一次"；第一次打开某个网站的（"允许 Claude 操作 https://xxx？"）一行里是"拒绝""始终允许""更多允许选项"，"允许一次"收在"更多允许选项"的下拉里（两种的对照表在 [09](09-approvals.md) 第 4 节）。手机上选了"允许一次"或"拒绝"时由 `-Action dialog` 去按（[09](09-approvals.md) 第 4 节）。Claude 6.28899 里实测：两个都是按钮、都认调用，名字正好是这两个词（旁边的快捷键提示不在名字里）；**键盘焦点不在按钮上时，调用只是把焦点移过来、框没有反应，焦点在按钮上时再调用才算点了**，所以脚本先 `SetFocus` 再调用（被控端 0.9.14，经过见 [05](05-handoff-tasks.md) 的 2.31）；"允许一次"往上数几层，第一层带文字的就是这个框自己的几段文字（"允许 Claude 在 " "uland.taobao.com" " 上" "执行 JavaScript" "？" 和一句说明），再往上就是整段对话。

**除了文字，"怎么按"也会变**。界面自动化里按一个按钮有两种方式：调用（Invoke，普通按钮）和展开（ExpandCollapse，带下拉的按钮、子菜单）。Claude 6.28899（2026-11-20 晚上升级到的）把标题栏"菜单"按钮从"只认调用"改成了"只认展开"，文字没变，被控端按老办法调用就一直按不动，10 秒后报 `ui-missing`（`menu` 这一步），手机上新建会话全部失败，打开已有会话不受影响（那条路上的按钮没变）。被控端 0.9.10 起每一步都是"优先用原来那种，不支持就换另一种"（`claude-ui.ps1` 的 `Press`）。两个版本里各按钮支持的方式：

| 按钮或菜单项 | 6.6395（当时这样按得动，没查过另一种行不行） | 6.28899（实测支持的） |
|---|---|---|
| 标题栏"菜单" | 调用 | 展开 |
| "文件"（菜单项） | 展开 | 展开 |
| "在新窗口中新建会话" | 调用 | 调用 |
| "<会话> 的更多选项" | 展开 | 展开 |
| 确认框的"允许一次""拒绝""始终允许" | 没查过 | 调用（要先把焦点放上去） |
| 确认框的"更多允许选项" | 没查过 | 展开 |

6.28899 里用程序展开"菜单"以后，那一排"文件 / 编辑 / 视图 / 转到 / 帮助"用程序收不回去（对按钮、对菜单调收起都没用，把焦点移到页面上也没用），要点了某个菜单项、在别处点一下或按 Esc 才消失，展开时主窗口还会被切到最前。正常流程最后会点"在新窗口中新建会话"，菜单自己就关了；只有中途失败、或者像第 6 节那样手工查看时才会留下。

## 6. Claude 升级后打不开了怎么查

手机上的提示对应 `session-failed` 的 `code`（协议 2.5）。被控端日志里会写是哪一步。日志打在标准输出上，同时写进 `%APPDATA%\remote-claude-host\logs\host.log`（0.9.4 起；超过 1 MB 把旧的改名成 `host.log.1`），会话相关的行以 `[会话]` 开头。窗口什么时候出现、什么时候关掉，平铺的日志 `%USERPROFILE%\.claude-window-tiler\tiler.log` 里也有（"发现新窗口""窗口关闭/隐藏"，带窗口句柄）：

- `ui-missing`，日志里有一行"没做成: ui-missing: <哪一步>"（0.9.10 起；之前打开、新建在点菜单这一段失败时日志里没有这一行，只能从手机上的提示猜）：那一步的按钮或菜单没找到，或者找到了但按不动。先看是不是 Claude 升级了（`Get-AppxPackage -Name '*Claude*'` 看版本，`Get-Process claude` 看它什么时候重启的，和日志里第一次失败的时刻对一下），再用下面的命令看 Claude 窗口里现在有哪些按钮和菜单项：文字变了就补进 `$L`；文字没变就看它支持哪种按法（把命令里的输出换成 `$_.GetSupportedPatterns()`），见第 5 节。只读，不会点任何东西：

  ```powershell
  Add-Type -AssemblyName UIAutomationClient; $w = [System.Windows.Automation.AutomationElement]::FromHandle([IntPtr]<窗口句柄>); $w.FindAll('Descendants', [System.Windows.Automation.Condition]::TrueCondition) | ForEach-Object { $_.Current.ControlType.ProgrammaticName + ' ' + $_.Current.Name } | Select-String '选项|打开|窗口|环境|菜单'
  ```

  窗口句柄用这条命令查，Claude 的主窗口标题是"Claude"，会话窗口的标题是会话名：

  ```powershell
  Add-Type -AssemblyName UIAutomationClient; [System.Windows.Automation.AutomationElement]::RootElement.FindAll('Children', [System.Windows.Automation.Condition]::TrueCondition) | Where-Object { $_.Current.ClassName -eq 'Chrome_WidgetWin_1' } | ForEach-Object { '{0} {1}' -f $_.Current.NativeWindowHandle, $_.Current.Name }
  ```

  新建会话报 `ui-missing: menu` 而 Claude 没升级、"菜单"按钮也好好的：可能是被控端认错了主窗口。新建时屏幕上已经有标题是"Claude"的窗口就不发链接，直接在它里面找"菜单"；2026-11-22 04:57 连着两次这样失败，Claude 的 `main.log` 里那两次都没有收到链接的记录（每收到一次链接有一行 `second-instance: the main window is made; it is shown now`），而主窗口当时收在托盘里。那个窗口是什么没查清。0.9.18 起这种情况会发 `claude://code/new` 再试一次，并在日志里记一行"在标题是"Claude"的窗口（句柄）里没找到"菜单"按钮……当时的窗口：…"，列出所有 Claude 窗口的句柄、标题、位置（[05](05-handoff-tasks.md) 的 2.33）。

- `no-main`：链接没把主窗口叫出来。检查 `claude://` 链接是否还归 Claude（注册表 `HKCU\Software\Classes\claude`），或者 Claude 是否改了链接格式。Claude 程序包 `app.asar` 里搜 `claudeURLHandler` 能看到它认哪些链接。
- `not-found`、列表是空的：记录文件的位置或字段变了，对照第 1 节的表查 `catalog.js`。
- 界面语言换成了中英文以外的：补 `$L`，或者把 Claude 的界面语言改回中文或英文。
- `stuck`：见下面"卡住的窗口"。

**卡住的窗口**（Claude 6.6395 上实测）：被控端打开会话后检查页面标题（`checkdoc`），对不上就关掉这个窗口再开一次；第二次还对不上就报 `stuck`。日志里那一行写着等了多久、页面标题是什么、和上次是不是同一个窗口。

**Claude 的窗口池**（界面代码在 `resources\ion-dist.asar`，搜 `[electron-window] Pool`）：会话窗口是主页面用 `window.open` 开出来的子窗口，内容由主页面画进去。关掉会话窗口时窗口不销毁：先藏起来，再把页面清空、页面标题置空，放回池里等下次用。池的规则是至少留 1 个、最多留 2 个、先放回的先用；池里多于 1 个时，多出来的 30 秒后销毁；已经开着两个或更多会话窗口时不预先补新窗口。所以平时池里藏着 1 个用过的窗口（藏着的窗口标题是空的），下次"打开方式 > 新建窗口"或"在新窗口中新建会话"拿到的就是它，句柄不变。池空了才新建窗口。关掉再开不会换窗口：池里只有它一个，放回去马上又拿出来。

**显示器关着时，从池里拿出来的窗口不刷新画面**（2026-11-20 查清并实测，0.9.5 起处理）。Claude 拿到窗口时马上就把新会话的标题和内容写进了页面，但显示器关着时这个重新显示出来的窗口不出画面，界面自动化读到的还是它关掉以前的样子，注入一次鼠标输入（显示器随之亮起）半秒内就恢复。和窗口在池里藏了多久无关，藏 1 分钟的也一样。原因推测是 Chromium 在显示器关着时把窗口都当成被挡住、不再重新计算，没有去证实。全新建出来的窗口当时是正常的（只见过一例）。表现：

- 打开会话：窗口标题换成了新会话，`checkdoc` 读到的页面标题还是上一个会话，日志是"页面停在别的会话上，等了 6.x 秒，页面标题：<上一个会话>"，重开拿回的是同一个窗口，最后报 `stuck`；
- 新建会话：新窗口里找不到环境按钮，日志是"没能自动选上环境: ui-missing env-button"。

两次事故都是这样：2026-11-19 17:35 到 17:36 开「明年项目计划与预算模板」6 次，2026-11-20 07:08 到 07:10 开两个会话 6 次、新建 1 次，13 次全部失败，全部落在息屏时段里（15:28 到 17:36:59、03:08 到 07:11:38）；显示器亮着时复用同一批窗口都是 0.0 秒显示出来，11-19 17:41 重放时 1.5 秒。11-20 07:11:11 再新建时，上一个没选上环境的窗口还开着、池是空的，Claude 新建了一个窗口，一切正常；07:11:38 显示器因为有输入亮了（多半是手机上点了画面），那个停住的窗口后来也是好的。

为什么手机上一直不亮：被控端只在有人看画面时用 `powerSaveBlocker` 防息屏，手机停在会话列表时不防；防息屏只能拦着不关，叫不醒已经关掉的显示器；打开、新建会话全程用界面自动化，不发鼠标键盘。0.9.5 起：

- 打开、新建会话前先注入一次鼠标微动（右移 1 像素再移回来，`win32.wakeDisplay`）叫醒显示器。电脑超过 60 秒没人操作时（显示器可能关着），记一行日志"电脑有 N 秒没人操作，显示器可能关着，先动一下鼠标叫醒"，等 1 秒再动 Claude；
- 会话窗口出来以后，检查页面、选环境的这段时间里先动一下，之后每 1.5 秒再动一下（`runUiAwake`），直到这一步做完；
- 有人开始看画面时（`rc:active` 从 0 变成有人）也先叫醒一次，免得手机上看到的一直是息屏前的画面。

实测（2026-11-20，用户电脑，Claude 6.6395）：关显示器 20 秒后，照被控端的步骤不叫醒就打开「推杆系统网口版调试」，拿到的是池里 1 分钟前刚关掉的窗口，6 秒后页面标题还是它上次的「每日代码审查脚本」；调 `win32.wakeDisplay()`，0.58 秒后显示对了，显示器也亮了。再关显示器 20 秒，用改好的 `host/sessions` 打开「每日代码审查脚本」：先叫醒、等 1 秒，窗口出来后 0.0 秒显示对，一共 3.1 秒。显示器亮着时复用池里的窗口 17 毫秒显示对。新建会话那条路没有实测，只有单元测试。

以后再复现要注意两点。一是要打开一个和池里那个窗口上次内容不同的会话：反复开同一个会话时，旧页面的标题和要等的标题一样，`checkdoc` 立刻通过，看不出停住（这次头三轮就这样白做了）。二是显示器状态要直接读（注册 `GUID_CONSOLE_DISPLAY_STATE` 通知，系统会马上发来当前状态），用 `SC_MONITORPOWER` 手动关的显示器不记进下面说的系统日志；手动关时消息只发给一个窗口，广播出去的话反应慢的窗口过一会儿会再关一次。

没人操作到时间自动息屏、有输入亮屏的时刻在系统日志里，事件来源 Kernel-Power、编号 566：`NextSessionType=1` 是息屏、`0` 是亮屏；`Reason=12` 是没人操作到时间了，`31`、`32` 是有输入。再遇到"卡住"时拿 `host.log` 里失败的时刻和它对一下：

```powershell
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-Kernel-Power'; Id=566; StartTime=(Get-Date).AddDays(-1)} | Sort-Object TimeCreated | ForEach-Object { $x = [xml]$_.ToXml(); '{0:MM-dd HH:mm:ss} {1}' -f $_.TimeCreated, (($x.Event.EventData.Data | Where-Object { $_.Name -in 'Reason','NextSessionType' } | ForEach-Object { $_.Name + '=' + $_.'#text' }) -join ' ') }
```

之前的两个说法要更正：一是"环境报了错的'新会话'窗口被复用后一直空白，要重启 Claude"，那次没有查显示器是不是关着，现在看多半是同一件事，没法回头确认；二是 0.9.4 猜的"会话太大、加载慢"，不是原因（15 MB、64 MB 的会话在亮屏时都是秒开）。0.9.4 加的"页面没有标题时最多等 20 秒"和日志文件留着：这次就是靠 `host.log` 查出来的。

## 7. 限制

- 电脑锁屏时做不了（界面自动化和窗口切换都被系统挡住），手机会提示先解锁。
- 打开和新建时 Claude 主窗口会闪一下；平铺没在运行时主窗口不会自动收起。
- 新建的会话窗口在手机上放弃（没发第一句话）后，电脑上会留着这个"新会话"窗口，要在电脑上关掉。
- 标题相同的两个会话同时开着时，"已开着"的判断按标题认窗口，可能认成另一个。关闭时核对标题也认不出这两个的区别。
- 关闭是给窗口发 `WM_CLOSE`，Claude 将来要是改成关窗口前弹确认，手机上会提示"没有关掉"（`still-open`），要在电脑上点。
- 只支持本机会话（`local_` 开头），云端会话和 SSH 环境下的会话没有测过。

## 8. Claude 升级后自检和自动修复

这一节的东西都是 2026-11-21 那次事故之后加的（[05](05-handoff-tasks.md) 的 2.28、2.29）：Claude 夜里自己升级，"菜单"按钮换了按法，直到用户第二天在手机上点"新建"才发现。用户要求"每次 Claude 有升级的时候自动检查一下，有需要修复的就修复一下"，并选了全自动（修好、测过后直接发版安装，不用问，事后通知）。分三层：

**自检本身**（`host/sessions/selfcheck.js`）：把手机上能触发的两件事在电脑上真的走一遍，只看结果不看界面细节，所以 Claude 怎么改都测得出来：

1. 读得到 Claude 的会话记录（`list()`）；
2. 新建：挑会话列表里第一个带环境的分组，`create()`，要窗口建出来、环境也自动选上，然后关掉这个"新会话"窗口（没发第一句话，不留会话）；
3. 打开：挑最近的、没开着窗口的、有标题的会话，`open()`，窗口里的页面要真的显示它，然后关掉这个窗口（关窗口不影响会话在后台跑；它本来就开着时不关）。

屏幕上会闪两下窗口，平铺各重排两次，一共四五秒。失败时记下 `code` 和卡在哪一步（`step`，比如 `ui-missing` / `menu`）。

**被控端自动跑**（`host/claudecheck.js`，0.9.11 起）：每分钟看一次正在运行的 `claude.exe` 的路径，从里面认版本（商店版是 `…\WindowsApps\Claude_6.28899.2.0_x64__…\app\claude.exe`）。下面任一种情况就记下"要自检"：还没自检过；Claude 版本变了；被控端自己换了版本（修好的被控端装上以后要再验一遍）；上次没通过、之后什么都没变、又过了 6 小时。要自检时等电脑空闲才跑：没锁屏、没人在看画面、键鼠 120 秒没人动、没有正在做的打开或新建。屏幕上一个 Claude 窗口都没有时认不出版本，不跑。

- 结果写进 `%LOCALAPPDATA%\RemoteClaude\selfcheck.json`：`claude`、`host`（两边的版本）、`checkedAt`、`ok`、`summary`（一句话）、`steps`（每一步的结果）。放在审批目录旁边而不是被控端的数据目录，是因为定时任务在 Claude 会话里读它，那里读 `%APPDATA%` 会被商店版 Claude 转到别处。
- 没通过：给手机发一条提醒（[09](09-approvals.md) 第 4 节末尾的"被控端自己发的提醒"），写明 Claude 的版本和哪一项卡在哪；之后通过了就收回。日志里是 `[自检]` 开头的几行。
- 被控端配置 `claudeSelfCheck` 写成 `false` 可以关掉。开发时另起的第二个被控端（设了 `RC_HOST_PROFILE`）不跑，除非再设 `RC_CLAUDE_CHECK=1`。

**命令行**（`scripts/claude-selfcheck.js`）：`node scripts/claude-selfcheck.js`（加 `--json` 只输出一行 JSON）用**工作目录里的源码**跑同一套自检，在普通 node 里跑，不用打包、不用起第二个被控端。改了 `host/sessions` 以后先拿它验证。退出码 0 都通过，1 有没通过的，2 没法跑（比如锁屏）。

**自动修复的定时任务 2026-11-22 起停用**（用户说的"先停掉这个功能"，经过见 [05](05-handoff-tasks.md) 的 2.34）。原因：Claude 桌面端的定时任务每跑一次就新开一个会话，每 3 小时一次，一天半攒了 11 个，其中 10 个是"自检通过，无需处理"或等审批超时的空跑，手机"全部会话"里一排同名的。停用是在定时任务里把它关掉（`update_scheduled_task` 的 `enabled: false`），任务和提示词都留着，要恢复就再打开。被控端自己的自检照常跑、没通过照常提醒手机；提醒里从 0.9.19 起写的是"在 RemoteClaude 的任意一个会话里说一声"（0.9.18 及以前写的是"定时任务几小时内会来处理"，停用后这句不对了）。

想恢复又不想攒会话时查过、没做的几条路：

- 让被控端在自检失败时才触发：做不到。Claude 6.28899 的程序包里认的链接只有 `claude://code/continue`、`claude://code/needs-input`、`claude://code/new`、`claude://cowork/shared-artifact`，没有从外部运行定时任务的入口（运行定时任务只有会话里的 `run_scheduled_task` 工具和界面上的"立即运行"）。
- 空跑的那次自己归档（`archive_session` 传 `self`；归档的会话被控端的列表不显示，`catalog.js` 本来就滤掉 `isArchived`）：没试。归档每次要经桌面端确认，定时任务的会话是默认权限模式，没验证过能不能免确认。
- 改成每天一次：每天还是多一个会话。
- 用 Claude Code 命令行在后台跑（不经桌面端，不占会话列表）：这台电脑上单独的 `claude` 命令行没登录，没往下做。

下面是停用前的做法，恢复时照旧。

**自动修复**（Claude 桌面端的定时任务 `remoteclaude-claude-upgrade-fix`，每 3 小时一次）：改代码要靠 Claude 自己。任务的提示词在 `%USERPROFILE%\.claude\scheduled-tasks\remoteclaude-claude-upgrade-fix\SKILL.md`，仓库里留了一份副本 `docs/claude-upgrade-fix-task.md`（改提示词要两边一起改，或者改完副本后用定时任务工具更新）。每次运行是一个全新的会话：

- 读 `selfcheck.json`，`ok` 为真或文件不存在就马上结束，什么都不做；
- 没通过：照本文第 5、6 节的办法查原因，只改 `host/sessions/`、`host/test/` 和文档；单元测试和命令行自检都通过后提交，打包被控端、核对包里的文件、用临时资料目录试运行、装到这台电脑、确认重新上线、上传安装包（[08](08-release-and-update.md) 第 1 节，`release.js --upload-only`）；装上去起不来就装回上一个版本；
- 做完（或者修不了）用 AskUserQuestion 告诉用户，这样手机上有通知；提交不自动推送，在这条通知里问要不要推；
- 处理过的情况记在 `%LOCALAPPDATA%\RemoteClaude\selfcheck-fix.json`，同一个"Claude 版本 + 被控端版本"修不了时 24 小时内不重复折腾。

定时任务只在 Claude 桌面端开着时运行；电脑上 Claude 没开着的话，错过的那次在下次打开时补跑。

**第一步不用审批，后面的要**（2026-11-21 改的，经过见 [05](05-handoff-tasks.md) 的 2.32）。定时任务的会话是默认权限模式，运行命令、读工作目录以外的文件都要审批，审批会推到手机；**49 分钟（2922 秒）没人批，Claude 桌面端就自己按拒绝处理，这次运行结束**。原来第一步用 PowerShell 读 `selfcheck.json`，于是每 3 小时都要用户批一次，没东西要修也一样，没批就白跑。现在：

- 第一步改用 Read 工具读（提示词里写的是这台电脑上的完整路径）；
- 仓库的本机设置 `.claude/settings.local.json`（不入库，只对在这个仓库里开的会话有效）给这两个文件开了只读的免审批许可：
  ```json
  { "permissions": { "allow": ["Read(~/AppData/Local/RemoteClaude/selfcheck.json)", "Read(~/AppData/Local/RemoteClaude/selfcheck-fix.json)"] } }
  ```
- 换一台电脑、重新克隆仓库后要把这个文件补上，否则第一步又会要审批。

改完手动跑了一次（`run_scheduled_task`）：15 秒结束，会话里只有一次 Read 调用，回复"自检通过，无需处理"，桌面端日志里没有 `Emitted tool permission request`。没单独试过"不加这条许可、只换成 Read 工具"会不会弹审批。真要修的时候，后面的命令（跑测试、打包、安装）照旧一条条到手机上问，这是有意留着的。
