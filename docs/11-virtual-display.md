# 11 虚拟屏与隐私屏

用户要的效果和 ToDesk 一样（2026-11-24 定的方案）：

- **虚拟屏**：电脑没有显示器、或者显示器断电时，手机开始控制这台电脑就临时建一块虚拟屏；控制结束自动去掉。
- **隐私屏**：从手机解锁电脑时，电脑上的真显示器盖一层黑幕，旁边的人看不到桌面；控制结束先锁屏再撤黑幕。

## 1. 为什么没有屏幕就用不了

- 没有亮着的显示输出时，Windows 不合成画面，采集到的是黑屏或停住的画面（Parsec、RealVNC 的文档，见第 2 节）。DP 接口的显示器关掉电源，Windows 一般当成拔掉了；HDMI 的看显示器。
- Claude 桌面端是 Electron（Chromium）。Chromium 在系统报告"显示器关了"或锁屏时，把所有窗口都当成被挡住，不再绘制（`ui/aura/native_window_occlusion_tracker_win.cc`，`screen_locked_ || !display_on_`）。0.9.5 查到的"打开会话卡住"就是这个（[07](07-claude-sessions.md) 第 6 节）。所以有虚拟屏也得在控制期间一直防息屏。
- 窗口被另一个**不透明**的普通窗口整个盖住，Chromium 也会停止绘制。它在判断时跳过这几种窗口（`ui/gfx/win/hwnd_util.cc` 的 `IsWindowVisibleAndFullyOpaque`）：带 `WS_EX_TRANSPARENT` 的（鼠标点击会穿过去）、带 `WS_EX_TOOLWINDOW` 的（任务栏除外）、分层窗口里透明度不到 255 或用了色键的、`WS_POPUP`（Chromium 自己的除外）、隐身（cloaked）的。黑幕就按这几种做（第 3 节）。

## 3. 实测（2026-11-24，本机：Windows 11、两块 3840×2160、RTX 4070 Ti SUPER）

### 3.1 黑幕会不会让 Claude 停止绘制

测试页是 Electron 45.3.4（Chromium 156），Claude 6.28899.6 用的是 Electron 45.3.3（同一个 Chromium 156）。页面每 0.5 秒记一次 `document.visibilityState` 和这段时间的 `requestAnimationFrame` 帧数。测试页设成置顶，免得别的窗口挡住它。

| 阶段 | 可见性 | 每 0.5 秒帧数 |
|---|---|---|
| 不盖 | visible | 25–31 |
| 普通不透明置顶窗口（`WS_CAPTION`）盖住（对照） | **hidden** | 0 |
| 撤掉 | visible | 恢复 |
| 黑幕盖住：`WS_POPUP`，`WS_EX_TOPMOST\|TRANSPARENT\|TOOLWINDOW\|LAYERED\|NOACTIVATE`，透明度 255，`WDA_EXCLUDEFROMCAPTURE` | **visible** | 29–31 |

黑幕盖着时，`WindowFromPoint` 在中心点拿到的是下面的测试窗口（被控端的点击能落到 Claude 上，`pointHitsWindow` 也认）。

第一次跑时对照组没生效（对照窗口出现后 Chromium 没重新算遮挡，测试页一直 visible），所以那次的结论不算；加了"切到前台 + 1 秒后原地挪一下"、测试页置顶以后才是上表。教训：测"不受影响"之前，先让对照组确实受影响。

### 3.2 虚拟显示驱动

驱动：[VirtualDrivers/Virtual-Display-Driver](https://github.com/VirtualDrivers/Virtual-Display-Driver) 25.7.23 的 `VirtualDisplayDriver-x86.Driver.Only.zip`（132118 字节，sha256 `e24210692b442b39af763536330ce78b423f19342b7a7792c26de3944e418b3a`；`.cat`、`.dll` 由 SignPath Foundation 签名，GlobalSign 签发，验签有效）。硬件 ID `Root\MttVDD`。用 SetupAPI 建根设备再装驱动（和 `devcon install` 一样）。

| 项 | 结果 |
|---|---|
| 装驱动 | 4.3 秒；4.5 秒后多出一块虚拟屏，默认 800×600（设置文件里分辨率列表的第一个） |
| 只留虚拟屏（`SetDisplayConfig` 只给虚拟屏那条路径，不写数据库） | 0.8 秒，两块真显示器关掉 |
| 只有虚拟屏时，测试页 | 一直 visible，每 0.5 秒约 15 帧（这块虚拟屏 30Hz） |
| 恢复（`SDC_USE_DATABASE_CURRENT`） | 0.4 秒回到三块 |
| 停用设备（`pnputil /disable-device`） | 0.4 秒后虚拟屏消失 |
| 启用设备 | 0.3 秒后回来 |
| 设备开着时直接删（`/remove-device`） | 提示要重启；设备从列表里没了，但虚拟屏还在，驱动还在它的 `WUDFHost` 里跑。结束只加载了 `mttvdd.dll` 的那个 `WUDFHost` 后消失。**卸载前先停用** |
| 安装时 | Windows 把 SignPath 的证书加进了 `LocalMachine\TrustedPublisher`，测完删掉了 |

### 3.3 远程解锁时会不会露出桌面

锁屏以后在每块真显示器上盖好黑幕（第 3.1 节的样式），再从手机解锁：

- 锁着时黑幕在锁屏界面下面，主屏照常显示锁屏画面，另一块屏是 Windows 自己的黑屏。
- 解锁那一刻直接是黑幕和提示字，**没有露出桌面**（用户在电脑前看的）。

前两次没测成：第一次脚本等锁屏只等 3 分钟就退出了；第二次锁屏后"是否锁屏"的判断（输入桌面打不开、或前台是 LockApp）短暂误报了一次"已解锁"，脚本以为解了锁，提前撤了黑幕。**做的时候用会话的锁屏、解锁事件判断，不要轮询**。

## 4. 设计

### 4.1 谁做什么

| 部分 | 做什么 |
|---|---|
| 被控端（普通权限） | 判断"控制开始、控制结束"；看有没有亮着的真显示器；让服务开关虚拟屏、隐私屏；虚拟屏开着期间每 2 秒报一次平安；控制期间防息屏 |
| 解锁服务（SYSTEM） | 启用、停用虚拟屏设备；在控制台会话的普通桌面上启动黑幕程序；收不到平安就自己收尾（隐私屏先锁屏再撤，虚拟屏停用） |
| 黑幕程序（`RemoteClaudeUnlock.exe --shade`，服务以 SYSTEM 身份在用户会话里启动） | 每块真显示器一块黑幕；挡本地键盘鼠标；本地按 Ctrl+Alt+Del 时锁屏退出 |
| 安装脚本 | 和解锁服务一起装驱动、建好设备、写设置，装完先停用设备 |
| 手机端 | 离开这台电脑时发"结束控制"；菜单里开关隐私屏；显示虚拟屏、隐私屏的状态 |

### 4.2 什么时候算"在控制"

安卓 App 开着"后台接收审批"时一直连着服务器（[09](09-approvals.md) 第 6 节），服务器还会为推送报一个编号为 `push` 的控制端，所以"连着"不等于"在控制"。按操作算：

- **开始**：真的控制端（不是 `push`）发来看画面、列会话、打开或新建会话、操作电脑的命令（解锁、平铺；锁定不算）。
- **结束**：控制端发"结束控制"（换到别的电脑、退出登录，被控端同时关掉它的画面连接）；或者 3 分钟里没人看画面、也没有上面这些请求；或者控制过的控制端都断开了（包括被控端和服务器断开、被顶替）、1 分钟里又没有控制端来操作。
- 断开后等 1 分钟：鸿蒙 App 一退到后台系统就把它冻住、连接断开，回到前台重新连上（编号也换了）。不等的话，开着隐私屏时切出去回个消息电脑就锁了。
- App 退到后台**不**发"结束控制"：开着隐私屏时，切出去回个消息就会让电脑锁屏。退到后台以后画面停了、也没有操作，3 分钟后照样结束；后台重新连上服务器时也不要窗口列表，免得被当成一次操作。

### 4.3 虚拟屏

- 控制开始、而且没有亮着的真显示器（`EnumDisplayDevicesW` 列出的接在桌面上的输出里，除了我们的虚拟屏没有别的）时启用设备；控制结束、或者插上了真显示器时停用。分辨率 1920×1080（设置文件里只留这一档）。
- 设备平时停用，不删。卸载时先停用再删（第 3.2 节）。
- 显示器只是关了电源但还连着（HDMI 常见）：系统认为屏还在，不建虚拟屏，只防息屏。
- 虚拟屏开着时一直防息屏：系统一关屏 Claude 就不画了（第 1 节）。

### 4.4 隐私屏

- 什么时候开：从手机解锁时自动开（App 设置里可关），手机菜单里也能手动开关。解锁时**先盖好黑幕再输密码**（第 3.3 节）。
- 黑幕：每块真显示器一块，样式见第 3.1 节；隔一会儿重新置顶一次。上半屏一行灰字"这台电脑正在被远程操作"，下半屏写怎么退出：电脑前的人按 Ctrl+Alt+Del、再选"锁定"或按 Esc，电脑会锁屏，用自己的密码登录；远程的人在 App 菜单里关掉隐私屏。
- 本地键鼠：黑幕程序装低级键盘、鼠标钩子，挡掉不是被控端发的输入（被控端注入时在 `dwExtraInfo` 里带一个标记）。
- 本地的人要用电脑：按 Ctrl+Alt+Del（系统不让程序拦这个组合键）。黑幕程序发现输入桌面切到了 Winlogon，等回到普通桌面就锁屏、撤黑幕、退出，要输密码才能进。
- 解锁失败的兜底：手机明确要隐私屏、黑幕却没盖上（黑幕程序没就绪），被控端不解锁，回 `privacy-failed`；按设置默认要、手机没说的（旧版 App），盖不上照常解锁。
- 电脑上的解锁服务是旧版（版本 3 以前，`STATUS` 回应里没有 `shade=`）：不盖、照常解锁，被控端日志里记一句。被控端会自动升级，解锁服务要在电脑前点"更新"才换新；不这样的话，手机默认要隐私屏，每台还没更新服务的电脑都从手机解不开了。
- 结束：控制结束时先锁屏再撤黑幕。被控端崩了：服务收不到平安，同样先锁屏再撤。

### 4.5 局限

- 黑幕和别的置顶窗口在同一层：通知弹窗、别的置顶窗口可能短暂浮在上面。本地键鼠挡掉以后打不开开始菜单。不像 RustDesk 那样注入系统进程去拿更高的层级（容易被杀毒拦）。
- 是黑屏，不是关屏，显示器背光还亮着。
- 锁屏界面、管理员确认框在安全桌面上，黑幕盖不住，也不需要盖。
- 不做"让真显示器无信号"（改显示拓扑）：Parsec、ToDesk、RustDesk 都出过"真显示器回不来"的问题。
- 黑幕要求 Win10 2004（19041）起（`WDA_EXCLUDEFROMCAPTURE`）。

## 5. 实现进度

### 5.1 虚拟屏（被控端 0.9.32、解锁服务版本 3）

| 部分 | 文件 |
|---|---|
| 判断"在控制" | `host/controlsession.js`（`push` 不算；`release`、断开、3 分钟没人看画面也没操作就结束）；页面从信令消息里看出操作（`host/renderer.js` 的 `CONTROL_TYPES`），`host-cmd` 的 `release` 在 `host/hostcmd.js` |
| 开关虚拟屏、报平安 | `host/vdisplay.js`（一次只和服务说一件事，一下子开开关关只按最后的结果办）；`host/win32.js` 的 `activeDisplays`（`EnumDisplayDevicesW`，显示器 ID 里有 `\MTT1337\` 的是我们的虚拟屏） |
| 分辨率 | 驱动设置里只有 1920×1080@60，但 Windows 记着这块屏上次用的分辨率（实测拿到 800×600），所以开出来以后被控端把它切到驱动支持的最大一档并记进系统设置（`fitVirtualMode`、`win32.displayModes`、`setDisplayMode`），下次开出来直接是对的 |
| 防息屏 | `host/main.js` 的 `updateKeepAwake`：有人看画面或者在控制期间都防 |
| 服务 | `UnlockService.cs` 的 `VirtualDisplay`、`DISPLAY ON/OFF`、`PING`、`DisplayWatchdog`，安装见 [06](06-unlock-service.md)"虚拟屏" |

**实测**（2026-11-24，本机，两块真显示器还接着）：

| 项 | 结果 |
|---|---|
| `install.ps1 -FromHost` | 退出码 0；服务换成版本 3 并在运行；设备 `ROOT\DISPLAY\0002` 记进了注册表，`VDDPATH` 写好 |
| `STATUS` | 开之前 `display=0`，`DISPLAY ON` 后 2.6 秒多出 `MTT1337` 那块屏、`display=1` |
| 报平安 | 每 2 秒 `PING`、持续 8 秒，虚拟屏一直在；停了以后约 16 秒服务自己停用，日志"被控端 15 秒没报平安，已停用虚拟屏" |
| 分辨率 | 驱动只报 1920×1080@60，Windows 用的却是 800×600；`fitVirtualMode` 改成 1920×1080@60，关掉再开直接是 1920×1080 |

**审查后改的**（code-reviewer、security-reviewer 各一轮，没有 CRITICAL；HIGH 两条都在被控端的失败路径上）：

- 关虚拟屏失败时不再报平安，交给服务的看门狗 15 秒后去关（原来 PING 会一直替它续着）；
- 以为开着、桌面上却看不到它（被看门狗关了），或者 PING 回 `display=` 不是 1：再要一次；PING 上一次没回来不再发；
- 改分辨率、摆窗口改在虚拟屏真的出现在桌面上时做（`display-added` 带过来），不再固定等 1.5 秒；
- `release` 时关掉那个控制端的画面连接，被控端和服务器断开、被顶替时结束控制，锁定电脑不算控制；
- 正在控制时不自动重启升级；退出时尽量发一次 `DISPLAY OFF`；
- 服务：一分钟最多切换 10 次；`PING` 不抢开关的锁，`DISPLAY` 等锁最多 0.5 秒；看门狗关不掉每秒重试，服务停止时也关；设备启用了却没能启动报 `display=2`、开的时候回 `ERR failed`；计时改用 `Stopwatch`；
- 安装：先写 `VDDPATH` 再装、`vdd_settings.xml` 也核对哈希、卸载时 `--uninstall-display` 失败就不卸服务、`pnputil` 不带 `/uninstall`。

改完重装服务再测（2026-11-24 18:58）：`PING` 关着回 `OK display=0`、开着回 `OK display=1`；已经开着时再 `DISPLAY ON` 不再动设备；最后一次请求后约 16 秒看门狗停用。没在真机上测：一分钟切换 10 次的限制（要连着开关十几次，窗口会被挪来挪去）、服务停止时关虚拟屏、安装时遇到别人装的同一个驱动。

**还没测**：真没有显示器的电脑上从手机看画面、打开会话（这台电脑接着两块真显示器，被控端不会开虚拟屏）；被控端主进程、页面里的接线只过了语法检查和单元测试。

### 5.2 隐私屏（被控端 0.9.32、解锁服务版本 3）

| 部分 | 文件 |
|---|---|
| 黑幕程序 | `UnlockService.cs` 的 `Shade`（`--shade`）：每块屏一块黑幕，低级键鼠钩子挡掉不带标记的输入，Ctrl+Alt+Del 以后锁屏退出，详见 [06](06-unlock-service.md)"隐私屏" |
| 服务 | `ShadeHost`（启动、停止）、`SHADE ON/OFF/END`、看门狗（和虚拟屏共用 `PING`），`Spawn.Start`（启动不等退出）、`Launcher.SessionToken` |
| 被控端 | `host/privacy.js`（开、关、结束，开着期间报平安，`PING` 回 `shade=0` 时记成关了）；`host/main.js` 的 `unlockWith`（解锁前先盖，手机带的 `privacy` 优先，没带按配置 `privacyOnUnlock`）、控制结束时 `end`、退出时 `SHADE END`；`host/win32.js` 注入的键鼠都带 `INJECT_MARK`；`host-cmd` 的 `privacy`（`host/hostcmd.js`）；`host-state` 带 `privacy` |

**实测**（2026-11-24 19:15–19:18，本机，用户在电脑前看着，后台每 2 秒替被控端 `PING`）：

| 步骤 | 结果 |
|---|---|
| `SHADE ON`（没锁屏时） | 两块屏各一块黑幕，样式 `0x080800A8`；用户确认整块黑、中间有字 |
| 不带标记的鼠标移动 | 被挡住，光标没动；带标记的照常移动 |
| `SHADE OFF` | 黑幕没了、`shade=0`，不带标记的移动又能动了，没有锁屏 |
| 盖着时用户按 Ctrl+Alt+Del 再按 Esc | 回到普通桌面时锁了屏、撤了黑幕，服务日志"黑幕程序自己退出了……已锁屏" |
| 锁着时 `SHADE ON`，用户从手机解锁 | 解锁那一刻直接是黑幕、没露桌面；之后 `locked=0 shade=1`，没有又锁上 |
| `SHADE END` | 0.5 秒，先锁屏再撤，日志"控制结束，撤了隐私屏：已锁屏" |

**没测**：被控端 15 秒没报平安时看门狗按 `END` 收尾（走的是和 `SHADE END` 同一个 `ShadeHost.Stop(true)`）；锁屏失败时断开会话；插拔显示器时重新铺黑幕；管理员确认框；被控端主进程、页面里的接线（只过了单元测试）；远程桌面接回的情形。

**审查后复测**（2026-11-24 21:29–21:31，本机，重装了改完的服务，用户在电脑前看着，后台每 2 秒 `PING shade`）：

| 步骤 | 结果 |
|---|---|
| `SHADE ON`（没锁屏时） | 139～152 毫秒回 `OK`（等到了就绪事件）；两块屏全黑，上半屏标题、下半屏退出提示都看得到；键鼠没反应 |
| 开着 80 秒 | 没有自己锁屏，日志里没有一次自检"没收到" |
| `SHADE OFF` | 撤了黑幕，日志"没有锁屏" |
| 盖着时按 Ctrl+Alt+Del 再按 Esc | 日志依次"输入桌面切到了「Winlogon」""要锁屏退出：电脑前有人按了 Ctrl+Alt+Del""已锁屏"；用户确认直接进锁屏画面、没露桌面，登录后是平常的桌面 |
| `SHADE ON` 3 秒后 `SHADE END` | 1 秒回 `OK`，`locked=1`；用户确认黑幕直接变成锁屏画面 |

第一次复测（20:36）黑幕开了 8 秒就锁了屏，原因没查清（见 [06](06-unlock-service.md)"隐私屏"的钩子一条）。**还没测**：锁着时开隐私屏、从手机解锁（被控端 0.9.32 没装到这台电脑上）；锁屏失败时断开会话；插拔显示器。

**审查后改的**（code-reviewer、security-reviewer 各一轮）：

- 被控端：撤黑幕的命令排到队里、轮到时再看开着没有；自己正在撤时 `PING` 回 `shade=0` 不当成有人按了 Ctrl+Alt+Del；各命令分开超时；`PING display`、`PING shade` 分开续租约；手机明确要隐私屏却没盖上就不解锁（`privacy-failed`）；解锁做完时控制已经结束了就先锁屏再撤。
- 服务、黑幕程序（详见 [06](06-unlock-service.md)"隐私屏"）：钩子挪到专门的线程、每 2 秒用 F24 自检，摘了就重装、再不行就锁屏；任何异常先锁屏；黑幕程序非正常退出时服务断开会话；黑幕、钩子就绪了才回 `OK`（就绪事件只有 SYSTEM 能设）；停不下来时先断开会话再结束它；只算控制台会话里的黑幕；插拔显示器时先铺新的再撤旧的；锁上以后再盖 0.8 秒；`SHADE ON` 一分钟最多 10 次；黑幕上写了怎么退出。
- 写进局限（06）：触摸、手写笔输入挡不住；UIAccess 程序的窗口能盖在上面；本机程序能连管道开隐私屏、替被控端续租约。

### 5.3 手机端（安卓、鸿蒙、网页）

- 换到别的电脑、退出登录时发 `host-cmd` 的 `release`；退到后台不发（第 4.2 节）。后台重新连上服务器时不要窗口列表，免得被当成一次操作、虚拟屏和防息屏白开 3 分钟。
- 解锁时带 `privacy`（设置里"解锁时打开隐私屏"，默认开）；菜单里开关隐私屏，按 `host-state` 的 `privacy` 显示"打开隐私屏""关闭隐私屏"，电脑锁着时不显示（解锁那一下按设置自动盖）。
- 回 `privacy-failed` 时提示隐私屏没盖上、没有解锁，可以重装解锁服务或在设置里关掉"解锁时打开隐私屏"。
- 同一批里还做了（用户 2026-11-24 一起提的）：解锁框写明解锁的是哪台电脑、锁定在打开时那台；记住解锁密码（[06](06-unlock-service.md)"记住解锁密码"）；审批通知推迟 60 秒（[09](09-approvals.md) 第 6 节）。
