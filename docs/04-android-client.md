# 04 安卓控制端设计

## 目标

做一个安卓原生 App，功能与现有网页控制端（`web/`）对齐，并利用原生能力把手机上的体验做得更好。App 只是控制端，**不改动协议、服务器和被控端**就能接入。

协议以 [03 通信协议](03-protocol.md) 为准。行为细节拿不准时，以 `web/app.js` 为参考实现，它约 700 行，覆盖了全部流程。

## 技术栈

| 项 | 建议 | 说明 |
|---|---|---|
| 语言与界面 | Kotlin + Jetpack Compose（Material 3），单 Activity | |
| 最低版本 | minSdk 26（Android 8.0），targetSdk 用开发时的最新稳定版 | 用户本人使用，不需要照顾老机型 |
| WebRTC | `io.getstream:stream-webrtc-android` | Google 已不再发布官方预编译包，这是目前维护最活跃的替代。Apache-2.0。实现时用的是 1.3.10 |
| 视频渲染 | 自写的 `VideoTextureView`（TextureView + WebRTC 的 `EglRenderer`） | 原计划用同系列 `stream-webrtc-android-ui` 的 `VideoTextureViewRenderer`。实现时改为自写：它按控件大小渲染，放大后是拉伸位图，小字会糊；自写版本让渲染缓冲区等于视频原始分辨率，再用变换矩阵缩放平移，放大后仍清晰 |
| WebSocket | OkHttp | 自动应答服务器心跳 |
| JSON | kotlinx.serialization，开启 `ignoreUnknownKeys` | 协议以后加字段时旧版 App 不会崩 |
| 异步与状态 | 协程 + StateFlow | 实现时没有用 ViewModel：连接状态挂在 Application 上的单例 `RemoteController` 里，屏幕旋转、界面重建都不影响连接 |
| 本地存储 | DataStore；登录令牌用 Android Keystore 里的 AES-GCM 密钥加密后再存 | 没有用已弃用的 `androidx.security:security-crypto`，直接调 Keystore |

代码在本仓库的 `android/` 目录下，结构和构建方法见 [android/README.md](../android/README.md)。实现情况和验收结果见 [05](05-handoff-tasks.md) 第 2 节。

## 模块划分

| 模块 | 职责 |
|---|---|
| `signaling` | 账号接口（`AuthApi`）、WebSocket 连接、鉴权、断线重连（退避 1 秒起，最长 10 秒）、消息收发与数据模型 |
| `rtc` | PeerConnection 的创建与销毁、应答协商、ICE、视频轨道和数据通道的接入 |
| `input` | 手势识别、坐标换算、事件合并限流、通过数据通道发送 |
| `ui` | 各页面与导航 |
| `data` | 服务器地址、邮箱、登录令牌、设备编号、上次查看的电脑和窗口等设置的读写 |

`signaling` 和 `rtc` 不依赖界面，生命周期挂在 Application 上，屏幕旋转时连接不能断。

## 页面

### 1. 账号页

一个页面三种模式，底部的链接互相切换：

| 模式 | 输入项 | 提交后 |
|---|---|---|
| 登录 | 邮箱、密码 | 进会话列表 |
| 注册 | 邮箱、验证码（旁边是"发送验证码"按钮，发出后倒计时）、密码 | 直接登录，进会话列表 |
| 找回密码 | 邮箱、验证码、新密码 | 切回登录模式，提示"密码已重置，请用新密码登录" |

- 错误提示直接用账号接口返回的 `message`（如"邮箱或密码不对""这个邮箱已经注册过了，请直接登录"）。
- 服务器地址在打包时写进 App（`BuildConfig.SERVER_ADDRESS`，取自本机打包配置 `deploy/prod/build.json` 的 `server`，见 [08](08-release-and-update.md) 第 1 节；仓库里不带地址）。写了地址的正式版不显示地址框，设置里也不显示。调试版、以及打包时没写地址的正式版（`SERVER_EDITABLE`）在三种模式的最上面多一个"服务器地址"框，没填时用写进去的地址，方便连本机或局域网里的测试服务器。
- 登录成功后保存邮箱、令牌和填过的服务器地址，下次打开直接进会话列表。**密码不落盘。**
- 信令鉴权失败（`bad-token`、`revoked`）时清掉令牌，回到登录模式并说明原因。
- 正式版只允许 `https`/`wss`。调试版可以允许明文，方便连局域网里的电脑测试。

### 2. 会话列表页

- 标题显示当前电脑的名字。
- 账号下有多台电脑、或当前电脑不在线时，标题下方显示电脑切换栏：每台一个按钮，在线的带绿点，离线的标"（离线）"。点哪台就列哪台的会话。
- 只有一台电脑在线时自动选它；记住上次选的电脑，下次打开直接用。
- 网格卡片：缩略图 + 标题。缩略图是协议里给的 data URL，Base64 解码成位图即可，不需要网络图片库。
- 卡片的先后就是电脑给的顺序，App 不排序。被控端 0.9.8 起按窗口在电脑屏幕上的位置排（屏 1 从左到右，再屏 2……，协议文档 2.4），点进某个窗口操作、刷新都不会让它换位置；0.9.7 及以前是最近操作过的在最前。
- 下拉刷新，进入页面时自动拉一次。
- 列表先到、缩略图后到（0.9.5，要被控端 0.9.7，协议文档 2.4）：要列表时告诉被控端缩略图可以后补。先到的那份没有图，收到就更新标题和个数、停掉刷新的转圈，缩略图沿用同一个窗口上一次的；新出现的窗口图还没到时先空着，不显示"无预览"。带图的那份到了再整份换掉。旧版被控端一次回完，和以前一样。
- 顶部状态条：正在重连、电脑不在线。
- 列表为空时给出说明："这个账号还没有电脑登录"、"这台电脑不在线"或"电脑上没有打开的 Claude 窗口"。
- 点卡片进入远程画面页。
- 电脑切换栏下面有两个页签："已打开 N"是上面说的窗口网格；"全部会话"见下面一节。切页签时各自刷新一次。
- 标题右边是"刷新"和"更多"（⋮）。"更多"见下面"右上角菜单"一节。

#### 右上角菜单：不点开窗口就操作电脑

0.9.4 起，会话列表页右上角是和画面页一样的"更多"菜单（原来这里是设置图标，现在"设置"在菜单里）。用户的要求（2026-11-20）：重排窗口这些功能"应该在外面就有，而不应该连上某个窗口才出现"，解锁也要有。

| 菜单项 | 什么时候有 | 做什么 |
|---|---|---|
| 重排窗口、所有会话提到最前、暂停自动平铺 / 恢复自动平铺 | 电脑在线、平铺在运行 | 同 [窗口平铺](#窗口平铺) |
| 锁定电脑 | 电脑没锁屏时显示；电脑不在线时置灰 | 先确认，再锁 |
| 解锁电脑 | 电脑锁屏时换成这一项；没装解锁服务时置灰 | 弹出输入密码的对话框 |
| 重排窗口、锁定电脑…（要先升级电脑上的被控端） | 被控端是 0.9.6 以前的版本 | 弹"电脑上的被控端版本太旧"，可以点"升级被控端" |
| 设置 | 总有 | 打开设置页 |

- 画面页的菜单多一项"显示统计信息 / 隐藏统计信息"（只对正在看的画面有意义），其余几项是同一份代码（`ui/HostMenu.kt`），显示条件在 `windows/HostCommands.kt`，有单元测试。
- 电脑锁屏时，电脑切换栏下面也出现和画面页一样的"电脑已锁屏"提示条，带"解锁"按钮。
- 这些命令走哪条路：连着画面、数据通道能用时走数据通道（协议 4.6、4.7，旧版被控端只认这条路）；没连画面时走信令通道的 `host-cmd`（协议 2.9）。会话列表页上的锁屏、平铺状态来自被控端推的 `host-state`，按电脑分别记，换电脑时跟着换；电脑下线、和服务器断开时作废。
- 没连画面时解锁，密码用被控端给的公钥加密后再发（`protocol/UnlockCipher.kt`，RSA-OAEP，哈希和 MGF1 都是 SHA-256；安卓默认的 MGF1 是 SHA-1，和被控端对不上，所以参数写明）。密码太长装不下、被控端刚启动公钥还没到时如实提示。
- 怎么认出旧版被控端：电脑回了窗口列表、却没推过 `host-state`（`AppState.hostTooOld`）。只看"还没收到状态"会在刚重连的那一下误报。

#### 关闭会话窗口

"已打开"里每张卡片的缩略图右上角有一个关闭按钮（深色圆底的 ×，看得见的 28dp，能点的范围 44dp），压在缩略图上（多半是缩略图两边的黑边），不挡标题。协议见 [03](03-protocol.md) 2.8，电脑上怎么关见 [07](07-claude-sessions.md) 第 4 节。

- 点了直接关，不确认（用户定的）：关闭只是关掉电脑上的这个窗口，会话不删，正在跑的任务接着跑，在"全部会话"里能再打开。
- 点了发 `close-window`（带卡片上的标题），按钮换成转圈、卡片变淡、点不了，最多等 10 秒。收到成功回执后卡片马上拿掉，提示"已关闭「…」，会话还在「全部会话」里"；电脑随后推来新的窗口列表。
- 失败按 `code` 提示："这个窗口刚换成了别的会话，没有关，列表已刷新"（`changed`，Claude 复用了这个句柄）、"电脑上的「…」没有关掉，请在电脑上看看"（`still-open`）等；`gone` 当作已经关掉，卡片拿掉。10 秒没回执提示"电脑没有回应"并刷新列表。
- Claude 主窗口（列表里 `closable` 为假）没有关闭按钮。
- 被控端是旧版本（列表里没有 `closable`）时按钮照样显示，点了弹"电脑上的被控端版本太旧"：说明要 0.9.1 以后的版本，可以点"升级被控端"让它马上升级（协议 2.6 的 `install`）。
- 关掉的正好是这台手机记着要自动回去看的窗口（`wantHwnd`），就忘掉它：Claude 以后可能拿这个句柄去开别的会话。正在看它的别的手机会收到 `window-closed`，照常提示"该窗口已关闭"回到列表。

#### 全部会话页签

列出电脑上 Claude 桌面端的全部会话（协议文档 2.5），按环境分组：

- 组头：环境名，下面一行小字是工作目录；保存过的环境右边有"新建"按钮。按目录分出来的组（会话不属于任何环境）和"无文件夹"组没有"新建"。
- 环境名用强调色（橙色），和下面白色的会话标题分开；名字后面的灰色数字是这个环境里的会话数。**点组头折叠或展开**它下面的会话，左边的箭头朝下是展开、朝右是折叠；折叠着也能点"新建"。哪些环境折叠着记在本机（`SettingsStore` 的 `collapsed_groups`），重开 App 还在。（0.9.4，用户 2026-11-20："环境字体颜色应该和他下面的会话字体颜色不同，点击环境可折叠和展开"）
- 每组先列最近的 5 个会话，多的点"显示全部 N 个"展开。每行是标题和最后活动时间（刚刚、5 分钟前、昨天、11月12日），已经开成单独窗口的标"已打开"。
- 点会话：发 `open-session`，弹出"正在电脑上打开「…」…"的等待框（已打开的写"正在切到"），收到 `session-opened` 后自动 `select` 那个窗口进入画面页。等待框里有"不等了"，点了以后就算电脑那边把窗口开出来也不再跳过去。最多等 60 秒。
- 点"新建"：先确认"在「X」新建会话？"，再发 `new-session`，同样等回执进画面页。新窗口是空的新会话，在画面里打第一句话。`envOk` 为假时提示"没能自动选上环境，请在画面里手动选"。
- 失败按 `session-failed` 的 `code` 提示，比如"电脑锁屏了，解锁后再试""没在 Claude 界面里找到要点的菜单（可能 Claude 升级了），请在电脑上操作""Claude 给的会话窗口卡住了……请在电脑上重启 Claude"。
- 电脑不回 `sessions`（被控端是 0.6.0 以前的版本）时提示更新被控端；电脑上没有 Claude 桌面端的记录时如实提示。
- 从画面页回来时，如果停在这个页签，刷新一次，"已打开"标记跟着变。

### 3. 远程画面页

这是核心页面，布局从上到下：

- **顶栏**：连接状态点（绿 / 黄 / 红）、当前会话标题（点击弹出会话切换面板）、还原缩放、收起或展开底部工具栏、更多（显示或隐藏统计信息、字体大小、重排窗口、所有会话提到最前、暂停或恢复自动平铺、锁定或解锁电脑、设置；除统计信息和字体大小外和会话列表页的菜单是同一套）。
- **画面区**：占满剩余空间，画面按比例完整显示并居中，支持横屏。
- **按键栏**：一行可横向滚动的按键。**0.9.2 起不显示**（用户 2026-11-19："现在感觉没有太大的用处，先把那一条隐藏掉"），代码留着，`RemoteScreen.kt` 的 `SHOW_KEY_BAR` 改成 `true` 就回来。
- **输入栏**："+"（弹出"图片""文件"两项）+ 文字输入框 +"发送"。原来"发送"左边还有"填入"（只填文字、不按回车），0.9.2 起也不显示（用户同日："感觉也没有什么太大的作用，也先去掉"），开关是 `SHOW_FILL_BUTTON`。按键栏不显示时输入栏上方留出和下方一样的 8dp 空隙。
- **进度条**：发图片、文件时出现在输入栏上方。图片依次显示"正在处理图片""正在发送图片 xx%""正在粘贴"；文件依次显示"正在读取文件""正在发送「名字」xx%（已发 / 总共）""已传到电脑，正在保存、粘贴路径"，右边有"取消"。
- **字体大小条**（0.9.7）：在"更多"菜单里点"字体大小"才出现，在画面区下面、输入栏上面（不压在画面上，调的时候整个窗口都看得见；底部工具栏收起时也照常显示）。一行：左边"字体大小 / 所有窗口一起变"，右边"缩小""默认""放大"三个按钮和"完成"。见下面"调电脑上的字体大小"。

#### 调电脑上的字体大小

用户的要求（2026-11-22）："再增加一个调整字体大小的功能：原理是选中一个 Claude 窗口，然后发送 Ctrl + 等于号。因为手机上需要调大字体才能看得更清楚一点。"

- 三个按钮各发一个按键事件给正在看的窗口（协议文档 4.3，被控端先把窗口切到前台再按），**被控端和服务器都不用改**：

  | 按钮 | 事件 | Claude 里的效果 |
  |---|---|---|
  | 放大 | `k: "=", m: 1`（Ctrl+=） | 放大一档 |
  | 缩小 | `k: "-", m: 1`（Ctrl+-） | 缩小一档 |
  | 默认 | `k: "0", m: 1`（Ctrl+0） | 回到 100% |

- 快捷键是从 Claude 桌面端 6.28899 的程序包（`app.asar`）里读出来的：菜单上"放大"写的是 Ctrl+加号，Ctrl+= 是它另外认的一个不显示的快捷键；一档是缩放级别 0.5（每档约 10%），范围 25%～500%。
- **电脑上所有 Claude 窗口一起变**，不只是正在看的这一个：Claude 把新的缩放级别设给它的每一个窗口。所以放在哪个会话的画面里调都一样，调一次就行。
- 按一下变一档，可以连着按，边按边看画面；条上不显示现在是百分之几（电脑不回报，手机只管按键）。
- 只在画面页有，会话列表页的菜单里没有：要对着一个窗口按，调完也要看着画面才知道合不合适。
- 和顶栏的"适应"、双指缩放不是一回事：那是手机上把画面放大了看，电脑上没变；这里是电脑上 Claude 的字真的变大，窗口大小不变，一屏能放下的字变少。
- 例外：键盘焦点正落在 Claude 窗口里自带浏览器的网页上时，Claude 只缩放那个网页。先在会话的对话区点一下再调。
- 代码：`input/FontZoom.kt`（三个快捷键，有单元测试）、`RemoteController.fontZoom`、`ui/RemoteScreen.kt` 的 `FontBar`。
- 网页控制端 0.4.0 起也有同样的一条：顶栏"⋮"菜单里点"字体大小"，发的是同样三个按键事件（`web/index.html` 的 `#fontBar`）。网页端的按键栏也从这一版起默认收起，在同一个菜单里点"显示按键栏"叫出来。

按键栏的内容和对应事件（按键栏现在不显示，留着这张表以后打开时用）：

| 按键 | 事件 |
|---|---|
| Esc | `k: "Escape"` |
| 回车 | `k: "Enter"` |
| 换行 | `k: "Enter", m: 2` |
| 退格 | `k: "Backspace"` |
| ↑ ↓ ← → | `k: "ArrowUp"` 等 |
| Tab / Shift+Tab | `k: "Tab"`，后者 `m: 2` |
| Del | `k: "Delete"` |
| 全选 / 复制 / 粘贴 / 撤销 | `k: "a"` / `"c"` / `"v"` / `"z"`，均 `m: 1` |

点按键栏时**不能让输入框失去焦点**，否则软键盘会收起又弹出。

按键栏不显示时这些键怎么办：

| 键 | 现在的做法 |
|---|---|
| 回车 | 输入框空着点"发送"，只发一次回车 |
| 换行 | 在手机输入框里直接换行，发出去保持多行，不会触发回车 |
| 粘贴 | 发图片、发文件时被控端自己粘贴，不用按 |
| Esc、退格、Del、方向键、Tab、全选、复制、撤销 | 没有替代。要停止 Claude 就点画面上 Claude 自己的停止按钮；Claude 输入框里已有的字没法从手机删。常要用的话把按键栏重新打开 |

### 4. 设置页

显示当前账号；退出登录（通知服务器作废令牌、清除本地令牌并断开）、保持屏幕常亮、触感反馈、显示统计信息、同步电脑剪贴板（0.9.6 起，默认开，见"同步电脑剪贴板"）、打开 App 时要求指纹或锁屏密码。

## 手势映射

| 手势 | 效果 | 发出的事件 |
|---|---|---|
| 单指轻点 | 左键单击 | `m`、`d`(b=0)、`u`(b=0) |
| 连续两次轻点 | 双击（电脑自己识别） | 两组单击 |
| 单指长按 | 右键单击，给一次震动 | `m`、`d`(b=2)、`u`(b=2) |
| 单指拖动 | 滚动远程内容 | 连续的 `w`，落点是手指按下的位置 |
| 双指捏合 | 缩放本地画面，1 到 6 倍 | 不发事件 |
| 双指拖动 | 平移本地画面 | 不发事件 |

细节：

- 轻点判定用系统的 `ViewConfiguration` 触摸容差；长按时长建议 550 毫秒，与网页端一致。
- 单指拖动在起手时**锁定方向**：横向位移超过纵向两倍才算横向滚动，否则只发纵向，避免上下滑动时混进横向滚动。
- 滚动量换算：手指移动的屏幕像素 × （视频高度 ÷ 画面显示高度）= 滚轮增量。手指向下拖 `dy` 为正。小数部分累积到下一次，不要丢。
- 双指手势期间抬起一指后，剩下那指不再触发任何操作，直到全部抬起。
- `m` 和 `w` 事件合并后每 16 毫秒最多各发一条。
- 建议加上惯性滚动：松手后按速度衰减继续发 `w`。网页端没有做。
- **拖拽模式**（建议做成工具栏上的开关，可放到第二版）：打开后单指拖动变成"按住左键拖动"，用来选中文字或拖滚动条。

## 坐标换算

协议要的是画面内 0 到 1 的相对坐标。设视频尺寸为 `vw × vh`，画面区尺寸为 `sw × sh`，当前缩放倍数 `zoom`，平移量 `(panX, panY)`：

```
fit      = min(sw / vw, sh / vh)            // 完整显示所需的基础缩放
显示宽高 = vw × fit × zoom, vh × fit × zoom
平移约束 = 显示宽度不超过 sw 时水平居中，否则 panX 限制在 [sw − 显示宽度, 0]；纵向同理
x = (触点X − panX) / 显示宽度
y = (触点Y − panY) / 显示高度
```

- `x`、`y` 落在 0 到 1 之外说明点在画面外的黑边上，这次轻点不发事件。
- **视频尺寸会变**：切换会话或电脑上调整窗口大小时分辨率跟着变。监听渲染器的分辨率变化回调，变了就重算布局并把缩放还原。
- 缩放以双指中点为中心，保持手指下的内容不动。算法参考 `web/app.js` 的 `layout()`、`zoomAt()`、`toRemote()`。

## 文字输入

**第一版用输入栏方案**：用户在本地输入框里用自己的输入法打好字，点"发送"发 `t` 再发 `Enter`。输入框为空时点"发送"只发回车。原来还有"填入"只发 `t`、不按回车，0.9.2 起不显示（见上面"远程画面页"），`sendText(text, pressEnter = false)` 还在。

这样做的原因：输入法的候选和联想过程全部留在手机本地，只把最终文字发过去，不会出现拼音字母先打到电脑上再被替换的问题，也最不容易出错。

可选的后续增强：

- **外接键盘**：把按键事件按协议映射成 `k` 或 `t`，映射规则参考 `web/app.js` 的键盘处理部分。
- **直接输入模式**：点画面后直接弹出软键盘，输入法每提交一段文字就立即发 `t`，删除键发 `Backspace`。需要自定义 `InputConnection`。

## WebRTC 接入要点

这些是容易出错的地方：

1. **App 是应答方**。收到 `offer` 后依次：设置对端描述 → 创建应答 → 设置本地描述 → 把应答通过信令发回去。
2. **ICE 候选要缓存**。对端描述设置完成之前收到的 `ice` 消息先存起来，之后再逐个添加。
3. **数据通道由被控端创建**。在 PeerConnection 的"收到数据通道"回调里拿到标签为 `input` 的通道，不要自己创建。
4. **数据通道必须发文本消息**。构造发送缓冲区时把"是否二进制"设为 `false`。被控端按字符串解析 JSON，发成二进制会被丢弃。
5. **ICE 服务器配置直接用 `auth-ok` 里的 `iceServers`**，每次新建 PeerConnection 都用最近一次收到的，因为 TURN 凭据会过期。
6. **用硬件解码**。解码器工厂用带硬件解码、软件兜底的默认实现。App 只收不发，但工厂仍需要一个编码器工厂参数，给默认的即可。
7. **不需要任何音视频权限**。没有音频轨道，不采集摄像头和麦克风。清单里只要网络相关权限，加上可选的震动权限。
8. **ICE 候选的 JSON 字段名**是 `candidate`、`sdpMid`、`sdpMLineIndex`，对应安卓 `IceCandidate` 的 `sdp`、`sdpMid`、`sdpMLineIndex`，注意第一个名字不一样。

需要在真机上确认的风险：

- **高分辨率竖屏画面的硬解**。Claude 窗口常见的尺寸是 1280×2088 这样的竖长画面，超过了 1080p 的高度。主流手机的硬件解码器能处理，但需要在目标手机上实测帧率和发热。有问题时先把被控端的 `codec` 设成 `H264` 试，再考虑给被控端加一个限制最大分辨率的配置项。2026-11-19 用户的小米手机（2211133C）收 VP9 1280×2088 能正常显示，电脑这边滑动时每秒发 28～30 帧（05 的 2.14）；手机这边实际显示多少帧还没从统计浮层确认。
- **16 KB 内存页**。Android 15 起部分设备使用 16 KB 页，原生库需要按 16 KB 对齐。选定 WebRTC 库版本后检查它的 `.so` 是否满足。只在自己手机上侧载时，以目标手机能否正常运行为准。

## 窗口平铺

电脑上的被控端自带 Claude 会话窗口的自动平铺（协议文档 4.7）。数据通道打开时被控端推 `tile-state`，`available` 为真时，画面页"更多"菜单里出现"重排窗口""所有会话提到最前""暂停自动平铺 / 恢复自动平铺"三项，分别发 `tile` 的 `arrange`、`raise`、`pause` / `resume`。

0.9.4 起会话列表页的"更多"菜单里也有这三项，不用先点开窗口：状态来自信令通道的 `host-state`，命令走 `host-cmd`（协议文档 2.9，被控端 0.9.6 起），见"会话列表页"的"右上角菜单"一节。

## 锁定与解锁

消息格式见 [03](03-protocol.md) 的 4.6，电脑上的解锁服务见 [06](06-unlock-service.md)。

- **锁屏提示**：被控端推来 `locked: true` 时，顶栏下面出现一条"电脑已锁屏"。电脑上装了解锁服务时右边是"解锁"按钮，没装时说明"要回到电脑前解锁"。锁屏时画面可能出不来，画面区提示"电脑锁屏了，解锁后显示画面"；解锁后被控端自动重新采集，不用重新选窗口。
- **解锁**：点"解锁"弹出对话框，输入 Windows 登录密码或 PIN，发 `unlock`，等最多 30 秒回执，按错误码提示。密码只在对话框的内存里，发出后就丢掉，不保存、不写日志。
- **锁定**："更多"菜单里的"锁定电脑"，先弹确认框：没装解锁服务时提醒"锁定后只能回到电脑前解锁"。确认后发 `lock-now`。电脑锁着时这一项换成"解锁电脑"（0.9.4）。
- **不会自动锁定**：切到后台、断开连接、退出登录都不会让电脑锁定。
- **不连画面**（0.9.4，被控端 0.9.6 起）：会话列表页也有锁屏提示条和菜单里的锁定、解锁，走信令通道的 `host-state`、`host-cmd`（协议文档 2.9）；解锁密码用被控端的公钥加密后才经服务器转发。见"会话列表页"的"右上角菜单"一节。解锁回执是 `closed`（连接断了）时提示"连接断开了，不知道电脑解锁了没有"，`bad-key`、`replayed` 提示"电脑上的被控端刚重启过，请再试一次"。

## 发图片

把手机里的图片粘贴进 Claude 的输入框，消息格式见 [03](03-protocol.md) 的 4.5。

1. 点输入栏左边的"+"，选"图片"，打开系统的照片选择器（`PickVisualMedia`，不用申请相册权限；没有系统选择器的老设备自动退回到文件选择）。
2. 选好后在后台线程处理：按拍摄方向转正，长边缩到 2048 像素以内；PNG（多半是截图）保持 PNG，超过 6 MB 才转 JPEG；其它格式转成质量 85 的 JPEG。重新编码顺带去掉了照片里的拍摄位置等元数据。代码在 `image/ImagePrep.kt`，尺寸计算在 `image/ImageSizing.kt`（有单元测试）。
3. 通过数据通道发 `img`，再把字节按 16 KB 一块用二进制帧发出，数据通道里排队超过 256 KB 就等一等，最后发 `img-end`。
4. 等被控端回执：`img-ok` 提示"图片已粘贴到输入框"；`err` 按错误码提示；20 秒没有回执，提示电脑上的被控端可能需要更新。
5. 图片只是粘贴进输入框，不会自动发送。传图期间可以继续打字、点"发送"，被控端会排在图片之后执行。

同一时间只发一张。打开选图界面时应用会进入后台，这期间**不断开画面连接**，选完马上能发；但最多保持 2 分钟，用户从选图界面直接回了桌面时照常断开。

## 发文件

把手机里任意类型的文件存到电脑上，再把它在电脑上的路径粘贴进 Claude 的输入框，Claude 按路径去读。消息格式见 [03](03-protocol.md) 的 4.8，要电脑被控端 0.9.0 以上。

1. 点"+"选"文件"（菜单里写着"存到电脑上，把路径粘贴进输入框，最大 50 MB"），打开系统的文件选择器（`OpenDocument`，类型 `*/*`，不用申请存储权限）。电脑上的被控端没推 `file-caps`（版本太旧）时不打开，提示"更新到 0.9.0 以后才能发文件"。
2. 读文件名和大小（`OpenableColumns`）。超过上限直接提示"「名字」太大了，最大 50 MB"，不发。网盘之类给不出大小的，先复制到 App 的缓存目录，边复制边数，超了就停。代码在 `files/FileSource.kt`。
3. 第一次发文件时建 `file` 数据通道（`PeerSession.openFileChannel`），等它打开（最多 10 秒）；发 `file`，再按 256 KB 一次在后台线程读文件，切成 16 KB 的二进制帧发出，一边算 SHA-256。通道里排队超过 1 MB 就等一等。发完发 `file-end`。常量和进度计算在 `files/FileUploads.kt`（有单元测试）。
4. 进度按"已交给通道的 − 通道里还排着的"算，每 100 毫秒更新一次。排着的数据 30 秒一点都没发出去，提示"传输卡住了，文件没有发完"。
5. 等回执最多 30 秒：`pasted` 为真提示"「名字」已存到电脑，路径已粘贴到输入框"（同名时显示电脑上实际的名字，如"报告 (1).pdf"）；`pasted` 为假提示"……但路径没能粘贴（电脑锁屏了），已放进输入框"，并把路径放进手机上的输入框，提示"……已放进下面的输入框，接着写要说的话再点发送"：用户解锁后在路径后面接着写，点"发送"时路径和话一起发出去；`err` 按错误码提示。
6. **取消**：进度条右边的"取消"。发 `file-cancel`（走输入通道），电脑删掉收到的部分。已经传完、等电脑保存时不能取消。
7. **发文件期间的文字**：文件和输入不在一条通道上，电脑不会把文字排在路径后面。所以发文件期间点"发送"不发，提示"文件还在发送，等路径粘贴好再发文字"，文字留在输入框里。按键栏、点击、滚动照常。
8. **离开画面**：发文件期间点返回，先问"文件还没发完，离开画面会断开连接，这个文件就不发了"，可以"接着发"。
9. **切到后台**：选文件时和选图一样不断开（最多 2 分钟）；正在发文件时切到后台也不断开，等它发完再断，最多 10 分钟。后台能不能接着发要看系统让不让 App 在后台运行，开着"后台接收审批"（常驻通知）时一般没问题。
10. 网络切换、画面连接断开时文件发不完，提示"画面连接断开了，文件没有发完"，要重新发。还不支持断点续传。

同一时间只发一个，发文件时不能发图片，反之亦然。

## 同步电脑剪贴板

看画面时，电脑上新复制的文字自动放进手机剪贴板，在别的 App 里直接粘贴。典型用法：在画面里点 Claude 回复下面的"复制"按钮，大约半秒后手机上提示"已复制电脑上的文字"。消息格式和电脑那边什么时候发见 [03](03-protocol.md) 的 4.9，要电脑被控端 0.9.9 以上，App 0.9.6 起。

- 只有自动同步，没有"取电脑剪贴板"的按钮（用户定的）。连上画面之前电脑上已经复制好的内容不会过来，要用就隔着画面再复制一次。
- 只同步文字，最多 100000 个字符；再长的提示"电脑上复制的文字太长，没有同步到手机"。剪贴板里是图片、文件时没有任何动静。
- 方向是单向的：手机上复制的东西不会自动到电脑，照旧用输入框发过去。手机发过去的长文字、图片、文件路径会经过电脑的剪贴板，这些不会再同步回来。
- `PeerSession` 在收数据通道消息的线程上认出 `clip`，交给 `ClipAssembler`（`protocol/ClipAssembler.kt`，有单元测试）拼块，拼齐了才回到主线程；`RemoteController.receiveClipboard` 用 `ClipboardManager.setPrimaryClip` 写进去，然后提示。不管系统版本每次都提示：这次复制发生在电脑那边，不提示的话看不出手机剪贴板换了内容（Android 13 起系统自己还会显示一下复制的内容）。
- 写剪贴板不需要权限。App 在后台时画面连接本来就断了，收不到。
- 设置里"同步电脑剪贴板"默认开；关掉后电脑照样会发，App 收到了不写剪贴板、不提示。
- 密码管理器复制的内容电脑不会发过来（它们带着"不要让监视剪贴板的程序处理"的标记）。

## 审批和提问

电脑上的 Claude Code 要审批工具调用或向用户提问时，在手机上作答，替代飞书插件。整体设计见 [09](09-approvals.md)，消息格式见 [03](03-protocol.md) 的 2.7。

- **列表**：账号下所有在线电脑推来的 `approvals` 合在一起，按出现时间排。会话列表页和远程画面页顶部有"有 N 个审批等你处理"的横幅（只有一条时直接显示"Claude 要审批 Bash"或"Claude 在问你"），点"处理"打开底部面板 `ui/ApprovalsSheet.kt`。
- **工具审批**：卡片上显示会话标题、目录、工具名、说明和参数（等宽字体，长的可展开），按钮"允许""拒绝""拒绝并说明"。说明文字原样转给 Claude。
- **提问**：每个问题列出选项（单选用圆点，多选用方框）和一个自己填的输入框，每个问题都要答才能"提交"；"不回答"等于拒绝这次提问。
- **回执**：提交后卡片显示"已提交，等电脑确认…"；收到 `approval-result` 的 `gone` 提示"这个审批已经在别处答了或已经结束"，`bad` 提示"答案不完整，请每个问题都选一下"。别处答了以后被控端推来的新列表里就没有这一条，卡片自动消失；全部处理完面板自动收起。
- **后台接收**：设置里"后台接收审批"默认开。开着时登录后启动前台服务 `approvals/ApprovalService.kt`（类型 `remoteMessaging`，常驻一条最低优先级的通知），App 切到后台也保持信令连接，只断开画面。安卓 12 起不能从后台启动前台服务，所以只在 App 打开时启动；开机和 App 升级后由 `BootReceiver` 尝试启动，失败就等下次打开 App。设置里还有"电池优化"一项，引导用户把 App 加入不优化名单。
- **通知**：App 在后台时每条新审批发一条高优先级通知（渠道"审批和提问"），点通知打开 App 并直接弹出面板。工具审批的通知上带"允许""拒绝"两个按钮（要求先解锁手机，`setAuthenticationRequired`），点了直接作答，失败另发一条通知说明。锁屏上只显示"Claude 要审批"或"Claude 在问你"和"解锁后查看"，不显示内容。审批结束（在哪里答的都一样）通知自动消失；App 在前台时不发通知。
- **权限**：安卓 13 起首次打开 App 时请求通知权限。App 锁（指纹）锁着的时候后台照常接收和通知，面板等解锁后才显示。

## 生命周期与网络

| 场景 | 处理 |
|---|---|
| 进入远程画面页 | 保持屏幕常亮 |
| App 切到后台 | 发 `stop`，关闭 PeerConnection。开着"后台接收审批"时保持 WebSocket（见"审批和提问"），否则也关掉。例外：系统身份验证界面、选图和选文件界面（最多 2 分钟）、正在发文件（发完为止，最多 10 分钟）期间不断开画面 |
| App 回到前台 | 用登录令牌重连，自动选回上次的电脑和窗口。WebSocket 没断（后台接收审批）时直接要一次窗口列表再选回去（0.9.0 起，之前会一直停在"正在连接画面…"） |
| 屏幕旋转 | 连接不断，只重算布局 |
| 网络切换（Wi-Fi 与移动网络之间） | 监听默认网络变化，立即重连信令并重新 `select`，不要等超时 |
| 信令断开 | 界面保留，后台按退避间隔重连，状态点变黄或红 |
| WebRTC 变为 `failed`，或 `disconnected` 超过 5 秒 | 重新发 `select` |
| 收到 `hosts`，当前电脑变为离线 | 关掉画面连接，提示"电脑不在线"；重新上线后自动拉列表并恢复 |
| 收到 `window-closed` | 提示并回到会话列表 |
| 收到 `auth-fail` 的 `bad-token` 或 `revoked` | 清除令牌，回到登录页并说明原因 |
| 进程被系统回收后重开 | 按"回到前台"处理 |

上次查看的窗口用 `hwnd` 记录。重连后先拉列表，列表里还有这个 `hwnd` 才自动选，没有就停在会话列表。

## 安全要求

- 正式版禁止明文流量，只连 `https`/`wss`。
- 密码不保存；登录令牌加密保存；退出登录时通知服务器作废并清除本地令牌。
- 建议提供"打开 App 时验证指纹或锁屏密码"的开关，默认开启。拿到这台手机就等于能在电脑上执行命令。
- 日志里不要打印密码、登录令牌、验证码和 TURN 凭据。
- 服务器证书由 Caddy 自动申请，是公网受信证书，不需要内置证书或关闭校验。

## 建议加的调试功能

**统计信息浮层**：从 PeerConnection 的统计里取出分辨率、帧率、码率、往返延迟，以及当前用的是直连还是中继。验收公网连通性时要靠它确认中继是否生效。
